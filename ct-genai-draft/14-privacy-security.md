## 3.2 مخاطر الخصوصية والأمن

سجلات الاختبار ولقطات الشاشة وتقارير العيوب قد تتضمن أسماء وبريدًا وبيانات سرية أو مفاتيح وصول. إدخالها إلى أداة GenAI ينشئ مسار معالجة جديدًا ينبغي فهمه، بما في ذلك التخزين والسجلات والمزود والأشخاص الذين يمكنهم الوصول.

## 3.2.1 المخاطر المرتبطة باستخدام GenAI

مخاطر الخصوصية تشمل كشف معلومات حساسة دون قصد في المخرجات، وفقد السيطرة على استخدام البيانات أو الاحتفاظ بها، وعدم توافق طريقة المعالجة مع المتطلبات التنظيمية المناسبة. السيليبس يذكر GDPR كمثال على إطار حماية بيانات؛ هذه مادة دراسية وليست تحديدًا للالتزامات القانونية على مشروع بعينه.

المخاطر الأمنية تشمل اختراق بنية الاختبار أو الوصول غير المصرح، واستغلال النموذج لتغيير سلوكه أو استخراج بيانات، ومدخلات خبيثة تضلل التحليل أو تؤثر في الناتج. قد تكون قاعدة البيانات أو واجهة API أو صلاحيات الأداة موضع المشكلة، وليس النموذج وحده.

## 3.2.2 أمثلة الثغرات ومتجهات الهجوم

| المتجه في السيليبس | الفكرة | مثال دفاعي للتعرف عليه |
|---|---|---|
| Context Manipulation | التلاعب بالسياق لمحاولة استخراج بيانات سرية | طلب يضغط على السياق ويوجه النموذج لكشف معلومات خارج المهمة |
| Request Manipulation | إدخال مادة تغيّر اتجاه الاستجابة | صورة تحتوي تعليمات غير مرتبطة بمعايير القبول |
| Data Poisoning | تلويث بيانات التدريب أو التحسين | تقييمات مزيفة لجودة تقارير مولّدة |
| Malicious Code Generation | استدراج توليد شيفرة ضارة | سكربت اختبار يتضمن اتصالًا خارجيًا غير مبرر |

يورد السيليبس احتمال كشف بيانات عند التلاعب بسياق طويل؛ لا نفهم ذلك كقاعدة أن تجاوز نافذة السياق يكشف بيانات التدريب حتمًا. المقصود التعرف إلى الخطر وتقييمه حسب التطبيق. النص داخل سجل أو صورة هو بيانات للتحليل، ولا يصبح تعليمات موثوقة لمجرد أن النموذج قرأه.

## 3.2.3 استراتيجيات الحماية

**تقليل البيانات Data Minimization:** أرسل فقط ما يلزم للمهمة، وتجنب الحسّاس دون مسوغ وصلاحية مناسبة. **إخفاء الهوية Anonymization** يهدف إلى منع ربط البيانات بالشخص، بينما **Pseudonymization** يستبدل المعرفات مع إمكان إعادة الربط عبر معلومات إضافية؛ لذلك ليس النوعان متكافئين في الخصوصية.

أمّن النقل والتخزين بالتشفير وضوابط الوصول، وحدد سياسات واضحة وتدريبًا على الاستخدام المسؤول. راجع المخرجات منهجيًا، ويمكن مقارنة نماذج إضافية مع مراعاة أن إرسال البيانات إلى مزود ثانٍ يحتاج صلاحية مناسبة هو الآخر.

اختيار البيئة يعتمد على مستوى السرية: عرض تجاري بضمانات مناسبة، سحابة آمنة، أو تشغيل داخل المؤسسة. الاسم «داخلي» لا يعفي من تأمين الصلاحيات والتحديثات. أضف تدقيقًا أمنيًا دوريًا وتقييم ثغرات، وتابع ممارسات الحماية المستجدة. في المؤسسة تشارك فرق الأمن والقانون والإدارة التقنية وCISO عند وجوده في القرار.

### دراسة حالة — HO-3.2.3

يريد مختبر تلخيص تقرير فشل. التقرير يحتوي بريد عميل وSession token، والأداة تحفظ تاريخ المحادثات، والسكربت المقترح يتصل بخدمة لا يحتاجها الاختبار.

| الملاحظة | الخطر | المعالجة المناسبة |
|---|---|---|
| بريد العميل | كشف هوية دون حاجة | استبداله ببيانات تدريبية مناسبة |
| Session token | تسريب وصول | إزالته ومعالجة تعرضه وفق سياسة الأمن |
| الاحتفاظ بالمحادثة | فقد السيطرة على دورة حياة البيانات | مراجعة سياسة الأداة وضبط الاحتفاظ والوصول |
| اتصال خارجي في السكربت | تسريب أو تنفيذ سلوك غير مطلوب | رفضه ومراجعة الكود قبل أي تشغيل |

حلّل أيضًا من يمكنه قراءة المحادثة، وما الذي يسجل في البنية، وكيف تُراقب الاستعمالات. الهدف ليس إرسال البيانات أولًا ثم البحث عن علاج؛ ابدأ بفحص المدخل والبيئة والصلاحيات.
