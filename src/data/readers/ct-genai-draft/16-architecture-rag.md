## 4.1 المقاربات المعمارية لبنية الاختبار

أداة الاختبار المدعومة بـLLM تربط تفاعل المستخدم ببيانات العمل وإجراءات المعالجة والتوليد. قد تكون دردشة أو واجهة متخصصة؛ القيمة ليست شكل المحادثة بل كيفية توفير السياق والتحقق من الناتج ودمجه في عملية الاختبار.

## 4.1.1 المكونات الأساسية

| المكوّن | المسؤولية | مثال |
|---|---|---|
| Front-end | استقبال طلب المختبر وعرض النتائج | اختيار قصة وطلب حالات اختبار |
| Back-end | المصادقة والاسترجاع وتجهيز التوجيه واستدعاء النموذج | جمع معايير القبول المسموح بها |
| LLM | توليد استجابة من التوجيه والسياق | مسودة الحالات والنتائج |
| Relational database | البيانات المنظمة | حالات ومعرّفات وعلاقاتها |
| Vector database | استرجاع دلالي بواسطة Embeddings | مقاطع توثيق ذات صلة بالسؤال |
| Post-processing | فحص وتحويل الناتج قبل العرض | التحقق من المخطط وربط الحالات بالمصادر |

يمكن أن يكون النموذج خدمة طرف ثالث عبر API أو نموذجًا داخل المؤسسة. يختلف النظام عن شاتبوت قواعد ثابتة لأنه يولد استجابات من السياق، وعن عميل/خادم بسيط لأن الخلفية تنسق مصادر متعددة ومراحل معالجة. مع ذلك تبقى المصادقة والصلاحيات مسؤولية التطبيق؛ النموذج ليس بديلًا عنها.

### تتبع طلب واحد

يختار المختبر قصة «التسجيل». تتحقق الخلفية من صلاحية المستخدم، وتسترجع الإصدار المعتمد، وتجهّز الطلب. يرجع النموذج مسودة، فتتحقق الأداة من الحقول ومعرّفات المتطلبات وتعرضها للمراجعة. النص السليم بنيويًا لا يعني صحة معناه؛ Post-processing قد يرفض نقص الحقول لكنه لا يحل كل أخطاء الاستدلال.

## 4.1.2 التوليد المعزز بالاسترجاع — RAG

**Retrieval-Augmented Generation** يضيف معلومات مسترجعة إلى سياق التوليد، بدل الاكتفاء بما تعلمه النموذج مسبقًا. الهدف زيادة الصلة والدقة وربط الناتج بمعلومات مناسبة للمهمة.

مرحلة الإعداد: تقسيم الوثائق إلى **Chunks**، تنظيفها ومعالجتها، ثم تمثيلها بـEmbeddings وحفظ المتجهات مع النصوص ومعلومات مصادرها. يذكر السيليبس 256–512 Token مثالًا لأحجام المقاطع، وليس قاعدة ثابتة لكل تطبيق؛ الحجم يجب أن يحافظ على المعنى ويناسب نافذة السياق والاسترجاع.

عند السؤال مرحلتان أساسيتان:

1. **Retrieval:** تمثيل السؤال واسترجاع مقاطع ذات صلة، غالبًا بتشابه المتجهات الدلالي.
2. **Generation:** إدخال المقاطع المختارة في السياق لتوليد جواب مستند إليها مع معرفة النموذج السابقة.

تستفيد الاختبارات من الوصول لوثائق المؤسسة ومستودعاتها ومتطلباتها وبياناتها الحديثة، بشرط تحديث الفهرس ومصادره. قاعدة متجهات قديمة لا تعرف تلقائيًا المتطلب الجديد، والتشابه الدلالي لا يضمن صحة الإصدار أو صلاحية الوصول.

### تجربة مقارنة — HO-4.1.2

جهّز وثيقتين تدريبيتين: النسخة القديمة تتطلب كلمة مرور من 8 محارف، والنسخة المعتمدة الجديدة من 12. اطلب حالات حدودية أولًا دون تزويد النموذج بالوثائق، ثم عبر نظام RAG أُدخلت إليه الوثيقة الجديدة بمعرّفها وإصدارها. افحص المقاطع المسترجعة قبل الحكم على الجواب.

المتوقع تعليميًا عند استرجاع المصدر الصحيح: حالات حول 12 حسب تقنية الحدود المختارة، مع إسناد للمتطلب. إذا ظهرت حدود 8، اسأل: هل أخطأ الاسترجاع باختيار نسخة قديمة، أم أخطأ التوليد رغم توفر النص الصحيح؟ أعد التجربة بسؤال ذي صياغة مختلفة وسجّل قوة الاسترجاع وحدوده.
