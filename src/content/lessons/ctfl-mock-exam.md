امتحان تجريبي كامل على منهج **ISTQB CTFL v4.0**، بالإنجليزي، بنفس شكل الامتحان الحقيقي: 40 سؤال، إجابة وحدة صحيحة لكل سؤال، والزمن 60 دقيقة (75 دقيقة لغير الناطقين بالإنجليزية). النجاح 26 من 40 (65%). توزيع الأسئلة على الفصول نفس توزيع الامتحان الرسمي: 8 / 6 / 4 / 11 / 9 / 2.

الأسئلة بالإنجليزي عن قصد — الامتحان الحقيقي بالإنجليزي، ولازم تتعوّد على صياغة السؤال والمصطلح بلغته. الحل بآخر الصفحة خلف زر «اكشف الحل».

> **Exam instructions:** 40 questions, 60 minutes, one correct answer per question. No penalty for wrong answers — never leave a question blank.

## Chapter 1 — Fundamentals of Testing (Q1–Q8)

**1.** Which of the following is a typical objective of testing?
A. Fixing the defects that are found
B. Building confidence in the level of quality of the test object
C. Proving that the software is defect-free
D. Evaluating the performance of the developers

**2.** A user receives an invoice showing an incorrect total amount. The incorrect total shown to the user is BEST described as:
A. An error
B. A defect
C. A failure
D. A root cause

**3.** Which testing principle explains why testers use techniques such as equivalence partitioning instead of trying every possible input?
A. Defects cluster together
B. Testing shows the presence, not the absence, of defects
C. Exhaustive testing is impossible
D. Tests wear out

**4.** Which statement BEST describes the difference between testing and debugging?
A. Testing locates and fixes defects, debugging finds failures
B. Testing can trigger failures; debugging finds and removes their causes
C. Testing and debugging are two names for the same activity
D. Debugging is always performed before testing

**5.** Which of the following is an example of quality assurance rather than quality control?
A. Executing a set of regression test cases
B. Analysing a defect report to find its cause
C. Improving the process the team uses to write requirements
D. Performing static analysis on the source code

**6.** A system has no known open defects, but users refuse to use it because it does not do what they need. Which principle does this illustrate?
A. Absence-of-errors fallacy
B. Defects cluster together
C. Early testing saves time and money
D. Testing is context dependent

**7.** Identifying test conditions, in other words deciding "what to test", is part of which test activity?
A. Test planning
B. Test analysis
C. Test implementation
D. Test execution

**8.** What is a typical benefit of a higher level of test independence?
A. Testers know the internal implementation better
B. Testers are likely to recognise different kinds of failures than the author
C. Communication with the development team becomes unnecessary
D. Developers no longer need to test their own code

## Chapter 2 — Testing Throughout the SDLC (Q9–Q14)

**9.** In a V-model, when should test analysis and design for system testing ideally start?
A. After the code has been written
B. During the corresponding requirements and specification activity
C. During test execution
D. After system integration testing is complete

**10.** Which of the following BEST describes a shift-left approach?
A. Moving testers into the operations team
B. Performing test activities earlier in the software development lifecycle
C. Postponing non-functional testing until after release
D. Automating every test case

**11.** Testing the interaction between the application and an external payment provider is MOST likely performed at which test level?
A. Component testing
B. Component integration testing
C. System integration testing
D. Unit testing

**12.** Which of the following is a test type rather than a test level?
A. Acceptance testing
B. Performance testing
C. System testing
D. Component testing

**13.** After a defect fix, tests are run on unchanged parts of the system to check that nothing else has been broken. This is:
A. Confirmation testing
B. Regression testing
C. Acceptance testing
D. Component testing

**14.** Which of the following triggers maintenance testing?
A. Writing new user stories for the next sprint
B. Migrating the system to a new platform
C. Reviewing the test plan
D. A new tester joining the team

## Chapter 3 — Static Testing (Q15–Q18)

**15.** Which work product CANNOT be examined by static testing?
A. A user story with its acceptance criteria
B. Source code
C. A third-party executable delivered without source code
D. A test plan

**16.** Which of the following is a typical benefit of static testing compared with dynamic testing?
A. It measures system behaviour under load
B. It detects defects earlier, when they are cheaper to fix
C. It requires an executable version of the system
D. It removes the need for dynamic testing

**17.** Which review type is the MOST formal, using defined roles, entry and exit criteria and metrics?
A. Informal review
B. Walkthrough
C. Technical review
D. Inspection

**18.** Which of the following is a success factor for reviews?
A. Reviewing a large work product in a single long session
B. Directing comments at the author rather than at the work product
C. Reviewing in small chunks with clear objectives
D. Skipping individual preparation to save time

## Chapter 4 — Test Analysis and Design (Q19–Q29)

**19.** A field accepts integers from 1 to 5000. Using three-value boundary value analysis, which values test the LOWER boundary?
A. 1 and 2
B. 0, 1 and 2
C. 0 and 1
D. 1, 2 and 3

**20.** For the same field, which of the following values belongs to the valid equivalence partition?
A. 0
B. 5001
C. 2500
D. -1

**21.** A booking record can be in the states created, confirmed or cancelled. Which technique is MOST appropriate?
A. Equivalence partitioning
B. State transition testing
C. Statement testing
D. Checklist-based testing

**22.** The expected result depends on combinations of several business conditions. Which technique is MOST appropriate?
A. Boundary value analysis
B. Decision table testing
C. Statement testing
D. Error guessing

**23.** Which statement about code coverage is correct?
A. 100% statement coverage guarantees 100% branch coverage
B. 100% branch coverage guarantees 100% statement coverage
C. Statement and branch coverage are always equal
D. Neither can be measured by tools

**24.** Which of the following is a white-box test technique?
A. Decision table testing
B. Branch testing
C. Exploratory testing
D. Boundary value analysis

**25.** Which of the following is an experience-based test technique?
A. Error guessing
B. Equivalence partitioning
C. State transition testing
D. Statement testing

**26.** Which statement BEST describes exploratory testing?
A. All tests are fully designed and documented before execution
B. Test design, execution and learning happen in parallel, usually within a time-boxed session
C. It can only be performed using an automation tool
D. It guarantees measurable structural coverage

**27.** In collaborative user story writing, the three C's are:
A. Card, Conversation, Confirmation
B. Code, Coverage, Confidence
C. Card, Coverage, Confirmation
D. Conversation, Coding, Closure

**28.** Which of the following BEST describes ATDD?
A. Acceptance tests are written after the code is complete
B. Acceptance tests are derived from the acceptance criteria before development starts
C. Only developers are allowed to write acceptance tests
D. It replaces component testing

**29.** Which of the following is NOT a characteristic of black-box test techniques?
A. Test cases can be designed before the code exists
B. They measure the structural coverage of the code
C. They are based on the specified behaviour of the test object
D. They can be applied at any test level

## Chapter 5 — Managing the Test Activities (Q30–Q38)

**30.** Which of the following is typically documented in a test plan?
A. The source code of the system under test
B. Entry criteria and exit criteria
C. The developers' personal calendars
D. The list of all defects ever found in the organisation

**31.** "No open defects with high severity remain" is an example of:
A. An entry criterion
B. An exit criterion
C. A test condition
D. A coverage metric

**32.** The level of a risk is determined by:
A. The number of defects already found
B. The likelihood of the risk occurring and its impact
C. The number of test cases executed
D. The size of the test team

**33.** Which of the following is a product risk rather than a project risk?
A. The test environment will be delivered late
B. A key tester is leaving the team
C. The payment calculation may produce incorrect amounts
D. The project budget has been reduced

**34.** Which estimation technique is based on the collective judgement of experts?
A. Metrics-based estimation
B. Wideband Delphi
C. Branch coverage
D. Boundary value analysis

**35.** In the test pyramid, tests at the TOP of the pyramid are typically:
A. Fast, cheap and numerous
B. Slower, more expensive and fewer
C. Only static analysis checks
D. Always executed manually

**36.** Which metric is MOST useful for reporting test progress during an iteration?
A. Number of lines of code written by developers
B. Percentage of planned test cases executed, with pass and fail status
C. Number of meetings attended by the test team
D. Number of testers in the team

**37.** What is the MAIN purpose of configuration management in testing?
A. To assign defects to the right developer
B. To keep testware identified and versioned, and linked to the correct version of the test object
C. To estimate the test effort for the next release
D. To prioritise test cases by risk

**38.** Above all, a good defect report should enable the developer to:
A. Estimate the release date
B. Reproduce the problem without contacting the tester
C. Approve the test plan
D. Decide which test level to use

## Chapter 6 — Test Tools (Q39–Q40)

**39.** Which of the following is a typical RISK of test automation?
A. Faster feedback from the pipeline
B. Underestimating the effort of maintaining the test scripts
C. More objective coverage measurement
D. Less repetitive manual effort

**40.** Tools that automatically run tests as part of a CI/CD pipeline belong to which tool category?
A. Static testing tools
B. DevOps tools
C. Test management tools
D. Non-functional testing tools
